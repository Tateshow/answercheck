# 回答一斉確認アプリ (MVP)

大人数（〜20人程度）でクイズや謎解きをおこなう際に、各プレーヤーの回答を集約し、ホストが正誤を判定した上で結果を一斉に公開するWebアプリです。設計内容は同名のドキュメント（要件定義・基本設計）を参照してください。

このMVPでは選択式問題のみを対象とし、自動採点＋ホストによる手動修正、一斉公開までの一連の流れを実装しています。ホスト画面・プレーヤー画面のURLは固定で、開催のたびにホストが発行する5桁のルームコードで接続します。

## 構成

- `server/index.js` — Express + Socket.io サーバー本体（ルームごとのイベントの振り分け）
- `server/roomManager.js` — ルーム（セッション）の作成・入室コード管理・ホスト再接続トークン管理
- `server/session.js` — 1ルーム分の状態管理・採点ロジック
- `server/questions.sample.json` — サンプル問題（選択式3問）
- `public/host.html` / `host.js` — ホスト画面
- `public/player.html` / `player.js` — プレーヤー画面

## 動かし方は2通り

| | 事前準備 | 開催のたびに必要な作業 | 参加できる範囲 |
| --- | --- | --- | --- |
| **A. クラウドにデプロイ（推奨）** | 最初の1回だけ（下記手順、ターミナル不要） | ホストがURLを開くだけ | インターネット経由でどこからでも |
| **B. ローカルネットワーク運用** | 毎回PCに Node.js が必要 | `npm start` をターミナルで実行 | 同じWi-Fi内のみ |

「毎回の準備を無くしたい」場合はAを、「インターネットに繋がずイベント会場だけで完結させたい」場合はBを選んでください。以下、それぞれの手順です。

---

## A. クラウドにデプロイする（最初の1回だけ・ターミナル不要）

無料のRenderというサービスに1回だけ配置すれば、以降は毎回ブラウザでURLを開くだけで使えます（Node.jsのインストールも`npm install`も不要になります）。GitHubとRenderのアカウント作成もブラウザ操作だけで完結します。

1. **GitHubにアップロード**
   1. https://github.com で無料アカウントを作成（すでにあれば不要）
   2. 右上の「+」→「New repository」で新しいリポジトリを作成（Public/Privateどちらでも可）
   3. 作成したリポジトリの画面で「Add file」→「Upload files」を選び、このzipを展開した中身一式（`node_modules`フォルダは除く）をドラッグ＆ドロップしてアップロードし、「Commit changes」

2. **Renderにデプロイ**
   1. https://render.com で無料アカウントを作成（GitHubアカウントでログイン可能）
   2. ダッシュボードで「New +」→「Web Service」を選択
   3. 先ほどのGitHubリポジトリを選択して連携
   4. 設定項目を入力：
      - Runtime: `Node`
      - Build Command: `npm install`
      - Start Command: `npm start`
      - Instance Type: `Free`
   5. 「Create Web Service」をクリック。数分でビルド・デプロイが完了し、`https://（サービス名）.onrender.com` のようなURLが発行される

3. **以降の使い方**
   - ホストはブラウザで `https://（サービス名）.onrender.com/host.html` を開くだけ
   - プレーヤーは `https://（サービス名）.onrender.com/player.html`（QRコードでも可）
   - 会場のWi-Fiは不要。参加者はスマホの回線からでも参加できる

**無料プランの注意点**: 15分間アクセスが無いとサーバーが自動的にスリープし、次にアクセスした人は起動まで約1分待つことがあります。イベント開始の1〜2分前にホスト画面を開いて起こしておくとスムーズです（月750時間まで無料で、通常の利用であれば無料枠で足ります）。

---

## B. ローカルネットワークで動かす（毎回ターミナル操作あり）

インターネットに繋がない環境や、都度の起動でも構わない場合はこちらです。

### 事前準備（初回のみ）

Node.js が入っていない場合は https://nodejs.org からLTS版をインストールしてください。

### 起動（開催のたびに）

```bash
cd answer-check-app
npm install
npm start
```

起動すると、ターミナルに以下のようなURLが表示されます。

- ホスト画面: `http://localhost:3000/host.html`
- プレーヤー画面（固定URL）: `http://<あなたのPCのIPアドレス>:3000/player.html`

同じWi-Fiに繋いだプレーヤーがこのURL（またはQRコード）でアクセスします。

## 使い方（A・B共通）

1. ホストがブラウザで `host.html` を開き、「新しいルームを作成する」を押す。5桁のルームコードとQRコードが発行される。
2. プレーヤーはQRコードを読み取るか固定の参加用URLにアクセスし、ルームコードとニックネームを入力して参加する（QRコード経由の場合はルームコードが自動入力される）。
3. ホストが問題一覧から「出題する」を押すと、全プレーヤーの画面に問題が表示される（受付時間は出題時に指定）。**途中参加したプレーヤーも、出題中であればそのまま問題に回答でき、次の問題からの参加も可能。**
4. プレーヤーが選択肢を回答する。
5. ホストが「受付を締め切る」を押すと自動採点され、回答一覧に○×が表示される。表記が怪しい場合など、必要な回答だけ「○にする」「×にする」で手動修正できる。
6. ホストが「結果を一斉公開する」を押すと、全プレーヤーの画面に正誤と得点が同時に表示される。
7. 次の問題へ進むか、最後に「セッションを終了して最終結果を表示」で得点ランキングを全員に表示する。

## ルームコードと再接続の仕組み

- **入室コード（5桁の数字）**: プレーヤーがルームに参加するための公開コード。ホスト画面に表示され、QRコード・URL（`?code=`パラメータ）にも埋め込まれる。
- **ホストの再接続**: ホスト画面をリロードしても、ブラウザに保存された非公開トークンで自動的に同じルームへ再接続する。この非公開トークンは入室コードとは別物なので、入室コードを知っているだけの参加者がホスト操作を行うことはできない。
- **プレーヤーの再接続**: 通信切断や画面のリロード後も、ブラウザに保存された情報で同じルーム・同じプレーヤーとして自動的に復帰する。
- 複数のルームを同時に開催できる（それぞれ別のホストが別のルームコードで並行運用可能）。

## トラブルシューティング

「ルームを作成する」ボタンを押しても画面が変わらない場合、多くはサーバーとブラウザのファイルのバージョンがずれていることが原因です。

1. （B運用の場合）起動中の `npm start` をターミナルで一度 `Ctrl+C` で完全に停止し、新しいファイル一式で上書き・再展開してから `npm install` → `npm start` で再起動する。（A運用の場合）Renderのダッシュボードで最新コードを再デプロイする。
2. ブラウザで `host.html` を開き直す（キャッシュが疑わしい場合はスーパーリロード〈Windows: Ctrl+Shift+R / Mac: Cmd+Shift+R〉するか、シークレットウィンドウで開く）。

静的ファイルはブラウザにキャッシュさせない設定にしてあるため、次回以降のアップデートではこの問題は起きにくくなっています。また、サーバーが応答しない場合はボタンを押してから数秒で画面にエラーメッセージが表示されるようにしてあります。

## 既知の制限（MVPスコープ）

- 選択式問題のみ対応（記述式は未対応 — 設計ドキュメントの拡張1で対応予定）
- ルームコードは5桁の数字のみで、総当たりで他人のルームに参加される可能性はゼロではない（プレーヤー参加のみが可能で、ホスト操作はできない設計にはしている）。長時間・不特定多数向けの運用にはより強固な認証を検討すること
- サーバー再起動（クラウドの無料プランのスリープからの復帰を含む）で全ルームの状態（参加者・得点）はリセットされる（インメモリ保持のため）
